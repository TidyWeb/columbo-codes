The Riverside Bike Hire Case

How to recognise an override, select the normal price, and apply a later discount without tying the logic in knots.

00 / Hear the whole story

The manager remembers one more thing

You are building the pricing logic for a bike-hire kiosk beside the river. The manager gives you the brief in two messages, an hour apart.

Message 01

Standard full-day hire is €15. If it is raining, the price falls to €10. On a public holiday, the price rises to €20 regardless of the weather.

Message 02 · just one more thing

Loyalty Card holders receive 15% off whatever they would normally pay. A child’s bike is always €5—regardless of the day, weather or membership.

Two messages. Four changing facts. One final price.

The late message is not an inconvenience to bolt onto finished code. It is evidence that must be understood before the decision structure is built.

Four changing facts means four answers must exist somewhere. If an early draft gathers only two answers, it cannot possibly represent the full brief.

03 / Classify the clues

Not every fact does the same kind of work

The original two labels are not enough. This case contains an override, selectors and a modifier. The difference determines where each question belongs.

!
Override

Child’s bike

Replaces every normal pricing rule. The result is €5, even on a holiday and even for a Loyalty Card holder.

Ask first. If yes, the pricing case is closed.
Selectors

Public holiday and rain

Choose which normal starting price applies. Holiday has priority over rain because the brief says holiday pricing applies regardless of weather.

Ask only when the override did not apply.
Modifier

Loyalty Card

Does not choose a normal starting price. It adjusts an eligible normal price after the selectors have finished.

Apply once, after the normal routes rejoin.
Columbo’s three-question test
  1. Does this fact cancel the ordinary rules? Override.
  2. Does it determine which ordinary result applies? Selector.
  3. Does it adjust an eligible result afterwards? Modifier.
04 / Establish precedence

Decision order is part of the evidence

The questions cannot be arranged by taste. Words such as “always” and “regardless” tell us which rules outrank the others.

1Child’s bike?Yes → €5 final price. Stop.
↓ No
2Public holiday?Yes → normal price €20.
↓ No
3Raining?Yes → €10. No → €15.
↓ Normal routes rejoin
4Loyalty Card?Yes → reduce eligible price by 15%. No → leave it unchanged.
Why holiday precedes rain

A rainy public holiday is still €20. Checking rain first could incorrectly settle on €10 before the stronger holiday rule is considered.

Why loyalty comes last

The same discount calculation can act on €10, €15 or €20. Repeating it inside all three routes would create unnecessary work.

05 / Follow the price

One value travels, but not every route visits every stage

The normal price routes all establish the same carried value. The override also establishes that value—but sends it directly to the final answer, bypassing the loyalty stage.

Code Tip

Indentation tells you which instructions belong to each question. Returning to an earlier left edge tells you that the indented block has finished. Remaining indented inside the normal-pricing else keeps the Loyalty Card decision away from the child-bike override.

Coding Overview

One decision chain runs from top to bottom

An if / elif / else chain is one complete decision unit. Python tests its conditions in order and takes the first route whose condition is true.

01 Ask the first question

If it is true, run its indented block and skip the rest of this chain.

02 Only after false, ask the next

An elif is evaluated only when every earlier condition in the same chain was false.

03 Use the fallback if nothing matched

else asks no question. It catches the remaining case after all earlier conditions were false.

Read it aloud

“Try the strongest rule. If that did not match, try the next rule. If neither matched, use the remaining answer.”

Only one branch in this chain can run.
Same unit · first match wins

if / elif / else

The aligned branch words belong to one chain. After one condition is true, the remaining branches become irrelevant and are skipped.

New unit · checked independently

A separate if

A new if begins another decision process. Python checks it even if an earlier, separate if already ran.

One careful correction:

Python does not somehow know which questions are true in advance. It evaluates the first condition. If that is false, it evaluates the next. It stops evaluating that chain as soon as it finds the first true condition.

Apply that to this case

The child-bike question forms the outer decision. Its else opens the normal-pricing world. Inside that world, holiday comes before rain because holiday has the wider effect: when holiday is true, rain no longer matters. Ordering the questions is therefore part of designing the program—not merely tidying the code afterwards.

07 / Keep the habit

A detective’s method for the next multipart problem

  1. Hear the whole story.Do later instructions alter, override or add to the earlier rules?
  2. Name the final result.What single value must the program eventually produce?
  3. List every changing fact.How many states does each fact have, and must the program ask for it?
  4. Classify each fact.Is it an override, selector or modifier?
  5. Read for precedence words.Do “always,” “unless,” “regardless” or “only” reveal which rule outranks another?
  6. Find the carried value.Which result must survive long enough to reach a later operation?
  7. Mark where routes rejoin or bypass.Does every route visit the next stage, or does an override leave early?
  8. Write the logic in plain English.Can every sentence make sense without mentally running the entire program?
  9. Sketch the silhouette.Show the nested shape before adding runnable expressions and calculations.
  10. Translate carefully.Now let Python describe a decision structure you already understand.
The clever part is not writing more branches. It is noticing which questions never needed to be asked on the same route.Case closed—until the manager remembers something else  😂
